# Pixel Transfer：RGB / 16 色截圖傳檔原型

將檔案壓縮、以密碼加密，轉成 16:9 的彩色資料圖像。發送端循環播放；接收端讀取本地螢幕中的遠端桌面區域，收齊分片後驗證、解密及還原。傳輸資料不需要交給 ChatGPT 或雲端服務。

提供兩種模式：`rgb` 每像素直接存 3 bytes，支援自訂圖像尺寸，預設 **1600 × 900、每張約 3.16 MB**，需要像素完全不變；`color16` 每張約 42.7 KiB，具有色彩校正與糾錯。兩端必須選擇相同模式。預設仍為已驗證合成失真的 `color16`；高容量使用下方的 `--mode rgb`。

## 視窗邊框與圖像尺寸

現在預設使用一般視窗播放，圖像外另有進度列。RGB 圖像按照選定尺寸直接編碼與顯示，**不縮圖**，接收端會自動辨識圖像尺寸，不需要另外設定。視窗不允許拖曳改變大小；如需另一個圖像尺寸，請重新產生。

| RGB 圖像尺寸 | 每張淨承載量（已扣除邊界與標頭） |
| --- | --- |
| 1280 × 720 | 1,852,376 bytes，約 1.85 MB |
| 1600 × 900（預設） | 3,161,816 bytes，約 3.16 MB |
| 1920 × 1080 | 4,816,856 bytes，約 4.82 MB |

使用 `--size 1280x720` 等明確尺寸，或 `--size auto` 依發送端桌面工作區估算大小；auto 預留視窗空間、維持 16:9，最高選到 1600 × 900。**遠端發送程式無法得知本地 RDP 用戶端實際可見區域**，因此 auto 是起始估算；若本地仍顯示不完整，請指定較小尺寸並重新產生。單純縮小 RDP 畫面仍會破壞 RGB 資料。

需要全螢幕時加 `--fullscreen`。一般視窗模式會先確認圖像及預留邊框能放入發送端工作區。Windows 使用工作區資訊扣除工作列，其他平台採螢幕尺寸並預留空間。明確尺寸允許 640 × 360 至 3840 × 2160 之間的矩形。

## 安裝

需要 Python 3.10 以上，兩端在此目錄執行：

```sh
python -m pip install -r requirements.txt
```

播放器及滑鼠選取工具使用 tkinter；部分 Linux 發行版需另外安裝系統的 `python3-tk`。macOS 需要授予終端機或 Python 螢幕錄製權限。Linux 螢幕擷取取決於桌面環境與 Pillow 的擷取支援。無圖形桌面的環境仍可產生、讀取 PNG。

## RDP 高容量模式：先校驗實際截圖

RDP 本身不能保證 RGB 像素完全不變。伺服器、用戶端、編碼、顯示縮放及色彩設定皆可能影響結果。32-bit 色彩或 4:4:4 設定本身，也不是逐像素無損的保證。以下校驗工具測的是實際畫面，不靠設定名稱推測。

遠端及本地都需要容納所選尺寸的完整圖像，不必占滿 Full HD。將 RDP 畫面以 1:1 顯示，停用會縮放整個遠端畫面的 Smart Sizing／縮放功能；Windows 程式已嘗試啟用 DPI awareness，仍須以校驗結果確認實際效果。保留完整四角，避免滑鼠游標、工具列或通知蓋住資料。

在遠端產生並顯示測試圖（輸出檔不能已存在）：

```sh
python probe.py create --out my-probe.png --size 1280x720 --show
```

圖像固定不動；等 RDP 畫面穩定後，在本地擷取 PNG 截圖，不要調整尺寸。也可以將套件內的 `rdp-probe-1280x720.png` 或 `rdp-probe-1600x900.png` 放在遠端以原尺寸顯示。接著在本地檢查截圖：

```sh
python probe.py check local-rdp-screenshot.png
```

工具會報告被改變的 RGB 通道數、像素數與最大差值。**資料區的通道不符數必須為零**才通過這次校驗。找不到原尺寸定位點時會提示檢查縮放；即使這次通過，也應在實際連線中多測幾次。PNG 只能保留截圖當下的像素，不能還原 RDP 已造成的失真。

校驗通過後，遠端發送：

```sh
python encode.py example.zip --out rgb-frames --mode rgb --size 1280x720 --play --fps 0.2
```

本地接收：

```sh
python decode.py --select --mode rgb --out restored.zip
```

這裡先每 5 秒換一張，讓 RDP 有時間更新完整高密度畫面；這只是起始設定，不是保證的傳輸速度。RGB 播放器不縮放圖像，可用區域不足時會拒絕播放，請指定更小尺寸。接收端需使用物理像素 1:1 的畫面；原尺寸圖像位於含有視窗邊框的較大截圖中也可定位。

RGB 模式使用 CRC32 檢查分片，並在收齊後以 AES-GCM 驗證整份資料；**沒有糾錯冗餘**，錯誤分片等待下一輪重讀。如果 RDP 持續改變像素，重播也不會解決，須調整畫面條件或改用 `color16`。它不是適用所有 RDP 設定的數 MB 傳輸保證。

## 16 色模式：發送端

```sh
python encode.py example.zip --out frames --play --fps 1
```

依提示輸入並確認密碼。`frames` 必須是尚不存在的資料夾。程式產生 PNG 後在一般視窗循環播放，按 Esc 結束；可加 `--fullscreen` 使用全螢幕。16 色模式的畫面會按可用空間縮小以保留完整四角；遠端桌面視窗也必須顯示完整圖像。預設每秒 1 張，接收端較慢時可用 `--fps 0.5`。

## 16 色模式：接收端

在本地螢幕上顯示遠端桌面，然後執行：

```sh
python decode.py --select --out restored.zip
```

用滑鼠框選包含四角定位點的完整圖像，可稍微多框一些白邊。選取工具覆蓋主螢幕。程式顯示分片進度，自動忽略重複資料，漏讀的圖像等待下一輪補齊。收滿後輸入相同密碼，驗證成功才建立輸出檔案；不覆寫既有檔案。關閉接收程式後，記憶體中的接收進度不保留。

也可直接指定區域（x,y,寬,高；實際座標依作業系統顯示設定）：

```sh
python decode.py --screen 100,100,1600,900 --out restored.zip
```

或讀取一張截圖、裝有所有截圖的資料夾：

```sh
python decode.py screenshots --out restored.zip
```

截圖可含多餘邊界，但不能缺少任何定位點。缺片時不輸出檔案，退出碼為 2。截圖資料夾只放同一次傳輸的圖片。螢幕模式可按 Ctrl+C 結束。

## 16 色圖像與容量

- PNG 固定為 1920 × 1080（16:9），四角黑色定位框的彩色中心各不相同。
- 上方 16 個大色塊用於量測當前畫面的色彩；中央資料格為 448 × 224 個 4 × 4 像素色塊，每個色塊 4 bits。
- RS(255,223) 糾錯，單一區塊可修正最多 16 個錯誤 bytes，並交錯排列以分散局部破損。這不等於可容忍任意比例的整張畫面損傷。
- 每張淨承載 43,674 bytes（約 42.7 KiB），已扣除糾錯及分片標頭。一份無法再壓縮的 1 MiB 檔案需要 25 張。每秒一張的一輪播放約 25 秒，完成時間取決於捕捉、辨識速度與漏片數。
- 原型上限為原始檔案 64 MiB，整份資料在記憶體處理，產生的 PNG 總容量可能遠大於原始檔案。

## 格式與安全

先使用 zlib 壓縮，只有縮小時才採用壓縮結果。接著以 Scrypt（隨機 16-byte salt，N=32768、r=8、p=1）從密碼產生 AES-256-GCM 金鑰；每次加密使用隨機 12-byte nonce。長度與壓縮旗標一同加密，標頭作為驗證資料。使用足夠長且不易猜測的密碼，並在兩端事先共用。

分片標頭包含版本、整份加密資料 SHA-256 前 16 bytes、分片索引、分片總數及長度。CRC32 用於篩除誤讀，完整性與密碼正確性由最終 AES-GCM 驗證。檔名不傳輸，由接收端 `--out` 指定。

新版 RGB 模式使用 `PTR4` 標頭，包含 32-bit 分片長度與圖像寬高；接收端也支援舊版固定 1920 × 1080 的 `PTR3`。16 色模式保留 `PTC2`。同一次接收不允許混入不同模式、圖像尺寸或不同傳輸。RGB 與 16 色模式沿用相同的 64 MiB 原始檔案上限。

`ecc.py` 是本原型隨附的 RS 傳輸糾錯實作；加密使用 cryptography 套件，沒有自行實作密碼演算法。

## 驗證與限制

```sh
python -m unittest -v
```

測試包含二進位／可壓縮／空檔案、錯誤密碼、竄改、缺片／重複／亂序、多張分片重組，以及圖像縮放、JPEG 色度抽樣、亮度變化、偏移背景及局部損傷。

RGB 額外測試包含 4 MB 完整檔案、一張滿容量加第二張分片的重組、較大截圖內的偏移定位、單一通道錯誤拒收、縮放與 JPEG 拒收，以及校驗圖錯誤數量。RGB 模式不宣稱能容忍那些在 16 色測試中可修復的失真。

變動尺寸測試涵蓋 640 × 360、1280 × 720、1600 × 900 的產生與還原、桌面邊框背景、校驗圖尺寸辨識、混合尺寸拒收、尺寸標頭不符拒收，以及 `PTR3` 舊版相容性。

16 色定位目前支援正向截圖的平移與水平／垂直縮放；RGB 只支援原尺寸正向截圖的平移，不支援縮放。兩者皆未支援旋轉、相機拍攝的透視變形。16 色可能受到遠端桌面的有損編碼影響；合成影像測試通過不代表所有遠端桌面設定都能成功。若進度停住，優先提高遠端桌面畫質、確認原尺寸顯示並降低播放速度。

目前尚未在真實遠端桌面連線中驗證播放器、框選與即時擷取，也沒有自動回傳完成訊號；接收端完成後需自行停止發送端。
