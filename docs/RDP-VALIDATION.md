# 可重複 RDP 校驗（Windows 預覽版）

目前真實 RDP／公司工作站測試：**尚未驗證**。Windows CI 的合成測試、WPF/GDI smoke 成功不代表 RDP 可靠。只在自己管理或已明確獲准測試的兩端執行；本流程不要求公司工作站權限，也不變更 RDP 政策。

## 準備與基準

1. 兩端使用同一份 PR Windows CI 的 `PixelTransfer-win-x64` 成品；記錄 PR/head commit。既有 v0.1.3 Release **尚未包含本次診斷**。不需公開儲存庫，只提供自己／既有協作者下載。
2. 在獲准的遠端執行 `./New-RdpTestInput.ps1 -OutputPath ./synthetic-8MiB.bin`，產生固定 8 MiB 合成資料；可用 `-SizeMiB 64` 測試更長接收。檔案不得已存在。記下 SHA256；本腳本不讀其他檔案。使用測試專用密碼，不要寫進結果。
3. 記錄兩端 Windows 版本、程式 build/commit、遠端桌面解析度、兩端 DPI 比例、RDP 客戶端 zoom、HDR 開／關／未知、資料圖尺寸、換圖秒數。不要填主機名稱、IP、帳號、公司名稱或密碼。程式自動測到的是**接收端主螢幕實體解析度及有效 DPI**，無法推知遠端解析度、RDP zoom、HDR 或壓縮設定。
4. 基準使用主螢幕、1280 × 720 校驗／資料图、RDP 100% 原始比例、每張 5 秒。圖像放不下就標示「無法執行」，不可縮圖後宣稱基準通過。
5. 清除通知並避免敏感視窗出現在擷取範圍。程式不保存截圖；仍建議只開合成畫面。每次開始校驗／接收會取代上一份記憶體診斷，**先匯出再開始下一次**，關閉程式會遺失尚未匯出的紀錄。

## 每個情境的固定步驟

1. 遠端「RDP 校驗」顯示校驗圖；本地先做一次「框選並校驗」。必須逐像素通過才繼續基準傳輸。
2. 本地按「連續校驗」並選擇 1／10／60 分鐘。框選完整圖像一次；每次量測後等待 1 秒，實際頻率取決於耗時。視窗會最小化，必要時還原後按「停止量測／接收」。期間保持框選位置固定；還原視窗可能遮擋校驗圖，需在紀錄標註。到「診斷紀錄」匯出 JSON。
3. 遠端「發送檔案」選擇合成檔、測試密碼及圖像設定；本地「自動尋找並接收」。基準做 3 次完整傳輸，每次收齊後先匯出 JSON，再解密至新檔名。
4. 本地執行 `Get-FileHash -LiteralPath ./received-synthetic.bin -Algorithm SHA256`，與合成原檔比對。記錄 SHA 相同／不同／未執行；JSON 的 `Completed` 只表示接收組裝完成，**不代表密碼解密或輸出檔比對已完成**。切勿使用敏感資料作測試。
5. 移動／遮擋情境需在尚未收齊前操作：例如使用 64 MiB、每張 10 秒，接收 2 個分片後把播放視窗移動約 100 px，遮擋 5 秒再移開。記錄操作相對秒數；等待自動重新定位。手動框選模式不會追蹤移動。
6. 每次只改一個條件，完整重跑並匯出新的 JSON。出錯／主動停止仍可匯出，勿將未完成的紀錄標成通過。

## 建議矩陣與目前狀態

| 情境 | 操作 | 自動涵蓋 | 真實 RDP |
| --- | --- | --- | --- |
| 100% 基準 | 1 分鐘校驗 + 3 次 8 MiB 接收／解密／SHA 比對 | 合成編解碼、WPF/GDI | 尚未驗證 |
| DPI 125/150/200% | 每次只改一端 DPI，RDP zoom 保持 100%，重新開啟程式 | 部分合成比例及 125% WPF | 尚未驗證 |
| 移動、遮擋、恢復 | 64 MiB/10 秒；移動後遮擋 5 秒 | 合成追蹤、真實本地 WPF 移窗 | 尚未驗證 |
| RDP 壓縮／持續變動畫面 | 依獲准設定測試，在資料圖外持續移動無敏感內容的視窗 | 合成損毀、持續更換分片 | 尚未驗證 |
| HDR | 若設備支援，關／開各重跑 | 未模擬 HDR | 尚未驗證 |
| 長時間 | 60 分鐘固定區域校驗；另做多輪 64 MiB 接收 | 統計記憶體上限回歸，非 60 分鐘壓力實測 | 尚未驗證 |

連續校驗是靜態公開圖案的採樣，不能證明持續換圖傳輸可靠，也無法知道兩次擷取間漏掉多少畫面。完成整份接收會自動停止；長時間接收請分多輪，分別保存報告。

## JSON 指標定義與隱私

- `SchemaVersion=1`；`ApplicationBuild` 來自 core assembly（CI 注入 head SHA）；`Mode`、`Evidence` 區分 synthetic、local-windows-smoke、offline-image、live-screen-environment-unconfirmed。`RealRdpValidation` 永遠是 `not-verified`：程式不能自動證明是否經過 RDP，實機結果需人工在下表標示。
- `StartedUtc/EndedUtc/ExportedUtc` 是 UTC；`ElapsedMs`、首個接受分片時間、每次擷取＋解析耗時使用單調時鐘。這些不是網路延遲或 RDP 端到端延遲；首片時間含初始 300 ms 等候，總時間也含輪詢等待。
- `Samples` 是完成解析的擷取／離線圖像數。自動接收同一輪可能先讀已追蹤區域再全螢幕搜尋，兩次各記一筆。`LocatedSamples/Samples` 是完整候選幾何的定位率，**候選可能是假定位點**；資料是否有效另看 `ValidPacketSamples`。校驗圖定位但像素不符也計入定位成功，另看 `ProbePasses/ProbeSamples`。
- `CrcFailureSamples` 是存在「標頭與長度有效但 CRC 不符」候選的擷取數；同張圖像多個候選／取樣相位失敗只計一次。它可能與有效分片同時存在，不能當作遺失封包數。無效標頭、找不到點、校驗圖像素不符不冒充 CRC 失敗。
- `ReceiveCycles/AcceptedCycles/DuplicateCycles/UniquePackets/TotalPackets` 區分輪詢、接受（含重複）、重複和新分片。同畫面其他傳輸即使解碼有效也不表示已被此接收接受。
- `TrackingLosses` 是原追蹤位置讀不到同一傳輸；`Reacquisitions` 是首次定位之後由全螢幕搜尋再次找到原傳輸（含同一輪立即找回）。`FullSearches` 是追蹤器的全螢幕搜尋路徑呼叫次數；追蹤區域恰好覆蓋全螢幕時仍屬 tracked 路徑。手動／校驗模式不使用追蹤器，數字為 0。
- 完整累計數持續保留；明細僅最近 256 筆，`DroppedDetails` 明示捨棄筆數，不提供全程逐筆時間線或 p95。每筆保留當時的本地主螢幕解析度／DPI、擷取尺寸、有效資料圖尺寸與還原比例；離線圖的 Display 為 0/未知，未知 DPI 為 null。圖像尺寸只在可判定時有值。
- 報告採欄位白名單：不含畫面、內容、加密資料、檔名／路徑、傳輸 ID、內容雜湊、密碼、帳號、主機、IP 或例外訊息。時間與顯示設定仍屬環境資訊，分享前請自行檢視。匯出是本機手動操作且禁止覆寫，沒有遙測或自動上傳。
- 擷取／解析拋例外的操作標成 `Error`，該次未完成量測不計入 Samples；保留此前已完成的數值，不寫入可能含敏感路徑的例外文字。`Stopped` 與零樣本不表示通過。資料截圖匯入沿用原流程，不產生新的接收診斷。

| 兩端 Windows、解析度、DPI | 未記錄 |
| RDP zoom、HDR、已知壓縮條件 | 未記錄／未知 |

| JSON 檔名（僅測試編號）、ElapsedMs | 無 |
| 定位率、有效分片擷取、CRC 失敗擷取、重定位數 | 未量測 |
| 校驗通過次數／樣本數；接收完整性；解密；SHA 比對 | 尚未驗證 |
| 結果 | 通過／失敗／未完成／尚未驗證／不適用 |

基準通過建議：整段校驗所有樣本逐像素通過，3 次接收都收齊、解密成功且合成原檔 SHA 一致；移動情境須記錄確實移動並成功找回。其他情境如有 CRC 失敗但重播後收齊，應報告「完整性通過，有重讀」，不可宣稱無誤碼。此標準只適用本次條件，不能推論其他工作站或 RDP 設定。
